# 008 — i18n (multilíngue pt-BR/en)

**Mod:** CustomClasses
**Status:** Backlog
**Criado:** 2026-06-07

## Visão geral

Tornar os textos do mod **bilíngues (en + pt-BR)** com fallback `en`, em duas frentes independentes:
- **(a) Launcher (server):** a **descrição** de cada classe/edition aparece na **língua configurada no servidor** (sem toggle próprio); fallback `en`. O **nome** da edition continua a chave (language-neutral).
- **(b) F12 (client):** um **seletor de língua** (pt-BR / english, **default english**) controla os textos renderizados pelo client (a UI dos multiplicadores do item 010 + os labels/tooltips do próprio F12).

## Comportamento atual

- **Descrição da edition:** o loader seta `DescriptionLocaleKey = def.Description` (texto literal) — [CustomClassesMod.cs:132](../../modded/Server/CustomClassesMod.cs#L132). `ServerLocalisationService.GetText` devolve a key verbatim quando não registrada, então o launcher mostra **sempre o mesmo texto** (hoje em pt), independente da língua do servidor.
- **Textos do client:** as strings da UI dos multiplicadores estão **fixas em pt-BR** no `MultiplierFormat` (item 010): "buff", "debuff", "Você possui … nessa skill devido à Classe …". Os labels do F12 (`EnableSkillMultipliers`, `ShowMultiplierOnSkills`) também são fixos em pt-BR.
- **Não há** seletor de língua nem descrição por idioma; o schema de classe tem `description` como **string única**.
- O servidor suporta os locales `en` e `pt-br` (entre outros) e expõe a língua desejada via `LocaleService.GetDesiredServerLocale()`.

## Comportamento desejado

- **(a)** O JSON da classe pode definir a descrição em **en + pt-BR**. No load, o mod resolve a descrição conforme `GetDesiredServerLocale()`: server `pt*` → texto pt-BR; qualquer outro (ou pt-BR ausente) → `en`. O launcher exibe essa descrição.
- **(b)** Um `ConfigEntry` de **idioma** no F12 (valores: `English` / `Português (BR)`, **default English**) define a língua dos textos do client. Trocar o valor muda os textos (na próxima vez que a tela/tooltip é montado). Língua desconhecida → `en`.
- **Retrocompatibilidade:** classes com `description` em **string simples** continuam válidas (tratada como `en`/fallback).

## Critérios de aceite

- [ ] Com o servidor em **inglês**, a descrição da classe no launcher aparece em **inglês**; com o servidor em **pt-br**, aparece em **português**.
- [ ] Classe **sem** tradução pt (só en) com servidor pt → launcher mostra o **inglês** (fallback), sem erro.
- [ ] Classe com `description` em **string simples** (formato legado) continua carregando — texto usado como fallback `en`.
- [ ] No F12, o seletor de idioma **default = English**; com ele em English, o tooltip do multiplicador diz "buff/debuff" em inglês; em Português (BR), em pt-BR.
- [ ] Trocar o seletor F12 e reabrir a tela de Skills muda o idioma dos textos do client.
- [ ] Idioma desconhecido/locale exótico → textos em **en** (sem crash) nos dois lados.
- [ ] O **nome** da edition no launcher continua igual (chave language-neutral) — não é traduzido.

## Corner cases

- [ ] **Server locale exótico** (de/fr/ru…) sem tradução nossa → descrição em `en`.
- [ ] **pt-pt vs pt-br:** tratar qualquer locale que comece com `pt` como português (usar a tradução pt-BR); demais → en.
- [ ] **Descrição vazia** num idioma (ex.: `pt` em branco) → cai em `en`; se `en` também vazio → usa o nome da classe (comportamento atual).
- [ ] **Seletor F12 alterado em runtime:** aplica na próxima montagem da tela/tooltip (não precisa reiniciar o jogo); documentar se exige reabrir a tela.
- [ ] **Texto com caracteres acentuados** (pt-BR) renderizado pela fonte do EFT e pelo launcher — confirmar que aparece correto (UTF-8).
- [ ] **Mistura:** servidor en + F12 em pt-BR → launcher em inglês, UI in-game em português (são frentes independentes; esperado).

## Fora de escopo

- Idiomas além de en e pt-BR.
- Traduzir **nomes de skill** (vêm do jogo/locale do EFT) ou **nomes de item**.
- Traduzir logs do servidor (sempre em pt-BR como hoje, uso interno).
- Localização das descrições via arquivos de locale do server (não há API pública de `AddText`; resolvemos a string no load).

### Schema de descrição multilíngue (decidido)

`description` aceita **string** (legado = `en`/fallback) **ou objeto** por idioma:

```jsonc
// forma legada (continua válida — tratada como en):
"description": "Combat medic specialised in surgery."

// forma bilíngue:
"description": { "en": "Combat medic…", "pt": "Médico de combate…" }
```

Resolução no load: server `pt*` → `pt` (se vazio/ausente, `en`); outro locale → `en`; tudo vazio → nome da classe. Um campo só, retrocompatível.
